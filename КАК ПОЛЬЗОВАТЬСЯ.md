# Как пользоваться: от нового проекта до релиза

Одна страница — весь путь по шагам. Что делать в каждой ситуации — [ШПАРГАЛКА.md](ШПАРГАЛКА.md), как устроен метод — [СПРАВОЧНИК.md](СПРАВОЧНИК.md). Установка комплекта на компьютер (один раз) — [УСТАНОВКА.md](УСТАНОВКА.md).

**Главное:** вы пишете правила и принимаете решения, агент пишет код и тесты, отдельный проверяющий (субагент `reviewer`) смотрит каждую задачу, а замки не дают пропустить шаги. Ваше дело — отвечать на вопросы, утверждать и читать отчёты.

## Шаг 0. Новая папка проекта (10 минут)

1. На GitHub в `claude-dev-kit` → **Releases** → скачайте `project-template.zip`, распакуйте в пустую папку проекта.
2. Откройте папку в VS Code. В терминале по очереди:
   - `git init`, затем коммит «chore: шаблон проекта»;
   - `pip install -r requirements.txt`;
   - `pre-commit install`;
   - `python scripts/validate.py` — должно быть **ПРОШЛО**.
3. Создайте **приватный** репозиторий на GitHub, отправьте туда проект, включите Dependabot alerts (Settings → Code security).
4. Откройте дашборд (страница о ходе работы) `exports/dashboard.html`: правый клик → **Show Preview**, вкладку — справа от диалога.

## Шаг 1. Бриф и допрос — `/new-project`

- Вставьте своими словами, что хотите получить. Это бриф (`docs/brief.md`) — агент сохранит его дословно.
- Агент задаёт вопросы пакетами, у каждого — рекомендуемый ответ и «почему». Можно отвечать «согласен со всеми, кроме 3».
- Итог: требования (ТР) и первые правила (ПР). Вы узнаёте в них свою задачу — значит, этап пройден.

## Шаг 2. Устройство — `/design`

- Агент предлагает стек (на чём пишем) — выбираете вы.
- Читаете одну страницу «Пересказ для заказчика» и отвечаете «ок» или правите.
- Утверждаете каждое правило (ПР) на примере с цифрами и выбираете инварианты (ИНВ — то, что верно всегда, как «актив = пассив»).
- Даёте эталон (`tests/golden/`) — заранее известные правильные ответы: закрытый период, ручной расчёт, выгрузка.

## Шаг 3. Нарезка — `/slice`

- Агент делит работу на задачи (Т) на одну сессию и пишет к ним сценарии «при таких данных → такой результат».
- **Главная точка вашего внимания:** утвердите сценарии на свежую голову. Утверждённые сценарии — это и есть тесты.

## Шаг 4. Задачи по кругу — `/ticket следующий`

Повторяйте для каждой задачи:

1. `/ticket следующий`.
2. Агент присылает анонс «▶ что изменится · как проверю · кто пишет код» и блок «Нужно от меня:». Ответьте «нет» или допишите свою проверку словами.
3. Ждите. Дашборд синий — агент работает; **оранжевый — нужны вы** (вопрос в блоке «Что нужно от вас»).
4. Читайте отчёт-светофор: 🟢 — готово, 🟡 — прочтите и решите, 🔴 — ответьте на «Нужно от меня:» (что делать с каждым цветом — [ШПАРГАЛКА.md](ШПАРГАЛКА.md), «Каждая задача»).
5. `/clear` — и снова `/ticket следующий`.

Значок 🔧 у задачи — повторные попытки кода; когда попытки кончатся, агент остановится и спросит вас (лимит — [global/CLAUDE.md](global/CLAUDE.md), «Лимит ремонта»). Иногда отчёт приходит с «Выборочной проверкой» — полным разбором случайной старой задачи; прочтите его.

**Когда Claude Code спрашивает разрешение** — читайте окно: удаляет ли команда, меняет ли базу, скачивает ли. Непонятно — «нет» и «объясни простыми словами». Изменение ваших тестов и эталона разрешайте, только если понимаете зачем.

**Нужно прерваться** — скажите «пауза». Вернуться — в новой сессии `/ticket Т-… продолжить`.

## Шаг 5. После функции — руками (10–15 минут)

Когда готова группа задач с видимым результатом — пройдите её сами на настоящих данных. Нашли ошибку — скажите агенту: появится новый сценарий и задача на исправление.

## Шаг 6. Релиз — `/release`

1. Когда все задачи релиза готовы — `/release`.
2. Агент проверяет безопасность, библиотеки, скорость на заявленном объёме, восстановление из бэкапа.
3. Слепой приёмщик (субагент `acceptor`, кода не видел) проверяет программу по брифу и требованиям. Итог — `docs/acceptance/release-N.md`, первая строка «подтверждено X из Y».
4. ❌ — агент заводит задачу на исправление; ⚪ «неясно» — вопрос вам.
5. Прочтите отчёт приёмки, пройдите программу руками (при замене старой системы — поработайте параллельно) и скажите «**релиз принят**» — агент поставит метку релиза, дорожная карта обновится.

## Красные флаги — остановиться и спросить

- В отчёте нет строки «ПРОШЛО» или строки про ревью.
- В анонсе были «Допущения», а в отчёте о них ни слова.
- Агент просит изменить ваш тест или эталон без понятной причины.
- Задачи часто передаются на модель выше — сложность при нарезке стоит пересмотреть.
