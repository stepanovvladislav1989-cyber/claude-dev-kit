# Шпаргалка: что делаю я

Правила и подробности — в [СПРАВОЧНИК.md](СПРАВОЧНИК.md). Здесь только мои действия.

## Новый проект

1. `claude-dev-kit` на GitHub → **Releases** → скачать `project-template.zip` → распаковать в папку нового проекта → `git init`, коммит, создать приватный репозиторий, отправить → включить Dependabot alerts.
2. VS Code → в терминале: `pip install -r requirements.txt`, `pre-commit install`, `python scripts/validate.py` → **ПРОШЛО**.
3. **`/new-project`** — отвечаю короткими сессиями, правлю черновики агента. Можно: «согласен со всеми, кроме 3».
4. **`/design`** — выбираю стек, утверждаю правила, даю эталон.
5. **`/slice`** — **главная точка внимания:** утверждаю задачи и сценарии порциями, на свежую голову.

## Тесты

Тесты придумывает и пишет агент по утверждённым сценариям. В начале каждой задачи агент коротко пишет, **что изменится для меня**, **как он это проверит** и **какая модель пишет код**, и спрашивает, хочу ли я добавить свою проверку. Отвечаю «нет» или пишу проверку словами.

## Каждая задача

`/ticket следующий` → читаю анонс «▶ что изменится · как проверю · модель» и отвечаю «нет» или своей проверкой → агент работает, субагент проверяет → читаю отчёт → `/clear` → снова `/ticket следующий`.

Модели агент выбирает сам по сложности задачи (низкая — Haiku, обычная — Sonnet, 💰 и высокая — Opus), замок не даст понизить. Мне нужно только, чтобы основная сессия была на Opus — если агент попросит, ввожу `/model opus`.

| Пришло | Делаю |
|---|---|
| 🟢 | Читаю два предложения |
| 🟢 💰 | То же + «Как считается»: совпадает с моим правилом? |
| 🟡 | Читаю полностью, решаю: принять или исправить |
| 🔴 | Отвечаю на вопрос |
| Выборочная проверка | Читаю полный разбор случайной старой задачи |
| Запрос на изменение моего теста или эталона | Разрешаю, только если понимаю зачем |

**Окно разрешения команды** — читаю только его, остальные команды агента не читаю. Смотрю три вещи: **удаляет** ли (`rm`, `del`, `DELETE`, `DROP`), **меняет ли базу** (`UPDATE`, `INSERT`, `ALTER`), **скачивает ли** (`pip install`, `curl`). Непонятно зачем → «нет» и «объясни простыми словами, что делает команда».

**Пауза:** «пауза» → в новой сессии «`/ticket Т-… продолжить`».

## После сессии

- **Отчёт:** проверки с числами — «логика 23 из 23, e2e 3 из 3». Все тесты зелёные — иначе коммита нет.
- **Коммит на GitHub** — уже отправлен агентом; перед ним pre-commit ещё раз прогнал все тесты и e2e, затем GitHub проверил в третий раз.
- **Дорожная карта** `docs/roadmap.md` — обновлена: что готово, что в работе, по релизам. Видна и на GitHub с телефона.

## Разбор кода — когда сам захочу

Кода в отчётах нет. Хочу посмотреть — вкладка **Source Control** в VS Code (изменения файлов) или прошу агента: «выгрузи код Т-012». В файле `exports/Т-012.md`: что сделано за сессию и итог проверок, новые файлы целиком, изменённые — «было → стало» (`-` удалено, `+` добавлено).

1. Открыть файл в VS Code → `Ctrl+A`, `Ctrl+C` → вставить в учебный чат (или перетащить файл в чат).
2. Спросить: «разбери новый код построчно» и «в изменениях — есть ли тихие ошибки».

Выгрузить самому: `python scripts/export_ticket.py Т-012`; без номера — всё, что ещё не закоммичено.
Эталон, данные и пароли в выгрузку не попадают.

Когда агент останавливается сам — стоп-лист в [global/CLAUDE.md](global/CLAUDE.md).

## Красные флаги — остановиться и разобраться

- Нет строки «ПРОШЛО» или про ревью; «ревью не запускалось».
- В анонсе есть «Допущения», а в отчёте о них ни слова.
- Задачи часто передаются на модель выше — назначения сложности стоит пересмотреть.
- «Как считается» не совпадает с правилом.
- Красный крестик на GitHub (вкладка Actions) или письмо Dependabot.
- Предупреждение «агент остановился после … попыток».

## После функции и приёмка

Все задачи релиза готовы → **`/release`**: агент проверяет безопасность, библиотеки, скорость на моём объёме, одновременную работу и восстановление из бэкапа. Затем я прогоняю релиз руками (и работаю параллельно со старой системой, если её заменяем) и говорю «релиз принят» — агент ставит метку и обновляет дорожную карту.

Порядок — [СПРАВОЧНИК.md](СПРАВОЧНИК.md), раздел «Ручное тестирование и приёмка».

## Режимы

- **Полный:** новый продукт — все шаги.
- **Средний:** новая функция — `/new-project` (допрос по функции) → правка правил → `/slice` → задачи.
- **Короткий:** мелкая правка — `/slice` на одну задачу (сценарии) → `/ticket`.
