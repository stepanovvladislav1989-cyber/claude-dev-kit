# Установка комплекта (Windows)

Время: 30–40 минут один раз. Дальше каждый новый проект — 2 минуты.

## Что в комплекте

```
global/            → кладётся в C:\Users\ИМЯ\.claude\  (работает во всех проектах)
  CLAUDE.md          кто я и как со мной общаться
  hooks/guard.py     замок: пароли и опасные команды
  skills/            6 скиллов
  agents/reviewer.md    субагент-ревьюер (Opus, только чтение), проверяет после каждой задачи
  agents/implementer.md субагент-исполнитель (Sonnet или Haiku — по сложности), пишет код обычных задач по плану
  settings.global.json   кусок настроек для подключения замка
project-template/  → шаблон нового проекта, скачивается как .zip из Releases
ШПАРГАЛКА.md       мои действия каждый день
СПРАВОЧНИК.md      полное описание метода (ТЗ) и карта источников
```

Замки написаны заново по мотивам открытых репозиториев, чужой код не копировался. Все проверены на тестовых примерах, но на вашем компьютере их нужно проверить ещё раз (шаг 5).

## Шаг 0. Проверить, что всё есть

В терминале VS Code:

```
git --version
python --version
claude --version
```

Если `python --version` печатает одно слово «Python» без номера или открывает Microsoft Store — это заглушка Windows, и замки (и глобальный, и проектные) молча не будут работать. Выключите её: Параметры → Приложения → Дополнительные параметры приложений → Псевдонимы выполнения приложений → выключить `python.exe` и `python3.exe`; затем выполните пункт ниже.

Если `python` не найден — в VS Code выберите интерпретатор Anaconda или добавьте его в PATH (список папок, где Windows ищет программы). Затем:

```
pip install pre-commit pytest
```

## Шаг 1. Глобальная часть

1. Откройте папку `C:\Users\ИМЯ\.claude\` (скрытая; если её нет — создайте).
2. Скопируйте туда:
   - `global\skills\` → `C:\Users\ИМЯ\.claude\skills\`
   - `global\agents\` → `C:\Users\ИМЯ\.claude\agents\`
   - `global\hooks\guard.py` → `C:\Users\ИМЯ\.claude\hooks\guard.py`
   - `global\CLAUDE.md` → `C:\Users\ИМЯ\.claude\CLAUDE.md`. Если файл уже есть — допишите содержимое в конец, не затирая.
3. Настройки:
   - Если `C:\Users\ИМЯ\.claude\settings.json` **нет** — скопируйте `settings.global.json` под именем `settings.json`.
   - Если **есть** — попросите Claude Code: «добавь в мой ~/.claude/settings.json хук из этого файла, ничего не удаляя».
   - В строке команды замените `ИМЯ` на имя вашей папки пользователя. Слэши — прямые: `C:/Users/ИМЯ/.claude/hooks/guard.py`.

## Шаг 2–3. Новый проект из шаблона

Шаблон лежит в этом же репозитории `claude-dev-kit`, во вкладке **Releases** — файл `project-template.zip`. Он собран из папки `project-template/` того же репозитория.

1. На странице репозитория `claude-dev-kit` → **Releases** → скачать `project-template.zip`.
2. Распаковать в пустую папку нового проекта (архив уже содержит скрытые `.claude`, `.github`, `.gitignore`, `.pre-commit-config.yaml`, `.env.example` — распаковщик Windows их не потеряет).
3. В этой папке: `git init`, коммит `chore: шаблон проекта`, создать новый **приватный** репозиторий на GitHub и отправить туда (`git push`).
4. В терминале:
   ```
   pip install -r requirements.txt
   pre-commit install
   python scripts/validate.py
   ```
   Должно быть: `ИТОГ: ПРОШЛО`.
5. На GitHub в новом репозитории: Settings → Code security → включить **Dependabot alerts** (бесплатные предупреждения об уязвимостях в библиотеках).
6. Запустите `claude` → введите `/new-project` (или словами: «запусти скилл new-project»).

**Важно про сам шаблон:** `project-template.zip` в Releases — снимок на момент публикации; когда его пересобирать — [СПРАВОЧНИК.md](СПРАВОЧНИК.md), раздел «Донастройка».

## Шаг 4. Существующий проект (например, уже начатый без этой схемы)

1. Скопируйте в корень проекта из шаблона: `.claude\`, `.github\`, `scripts\`, `tests\acceptance`, `tests\agent`, `tests\e2e`, `tests\golden`, `.pre-commit-config.yaml`, недостающие строки `.gitignore`, шаблоны из `docs\` (существующие документы не затирать).
2. `pre-commit install`, затем `python scripts/validate.py`.
3. `/new-project` → сказать: «существующий проект, ТЗ лежит в …». Скилл пойдёт по ТЗ разделами и выпишет ТР и ПР со ссылками на пункты.
4. `/slice` — задачи только на оставшуюся работу. Первым разумно взять самый рискованный участок оставшейся работы, пока кода мало.

## Шаг 5. Проверка замков (обязательно, 5 минут)

В проекте, запущенном из шаблона, в Claude Code по очереди:

| Что сказать агенту | Ожидаемо |
|---|---|
| «Прочитай файл .env» (создайте пустой .env заранее) | Отказ: «ЗАПРЕЩЕНО защитным хуком» |
| «Выполни rm -rf tests/agent» | Отказ |
| «Выполни через PowerShell: Remove-Item tests/agent -Recurse» | Отказ |
| «Через PowerShell допиши строку в tests/acceptance/README.md командой Add-Content» | Claude Code спрашивает ваше разрешение |
| «Добавь строку в tests/acceptance/README.md» (существующий файл) | Claude Code спрашивает ваше разрешение |
| «Создай новый файл tests/acceptance/test_proba.py» | Создаётся без вопроса |
| «Создай src/x.py и тест tests/agent/test_x.py, который падает, и заверши работу» | Агент не может завершить, пишет «Проверка НЕ ПРОШЛА» и пытается исправить |
| Создайте src/y.py (тест зелёный), но не запускайте `scripts/mark_reviewed.py`, и завершите работу | Агент не может завершить, пишет «ревью не подтверждено» |
| «Закоммить src/y.py» (без ревью) | Коммит не создаётся: «ревью … не отмечено» |
| «Выполни find tests/golden -name "*.md" -delete» | Claude Code спрашивает ваше разрешение |
| «Выполни cd tests && sed -i s/a/b/ golden/README.md», затем `python scripts/validate.py` | Замок может не спросить, но проверка — НЕ ПРОШЛО: «изменены … без разрешения» |
| «Поправь .claude/hooks/stop_red.py» | Claude Code спрашивает ваше разрешение |
| В терминале: сделать коммит при падающем тесте | Коммит не создаётся |
| «Сделай коммит с --no-verify» | Отказ |
| «Выполни psql -c "UPDATE …"» (любая таблица) | Отказ: «изменение базы разовой командой» |
| «Выполни git checkout -- .» | Отказ: «отмена всех несохранённых изменений» |
| Создайте задачу docs/tickets/Т-900-proba.md со строками `**Вид:** 💰 деньги` и `**Статус:** в работе`, затем «запусти субагента implementer» | Отказ: «замком выбора модели … 💰-задача» |
| «Запусти субагента reviewer на модели sonnet» | Отказ: «Ревью — только Opus» |
| С той же задачей Т-900 введите `/clear` и спросите «какая задача текущая?» | Агент называет Т-900 — журнал подгрузил замок session_context |
| Отправить на GitHub коммит с падающим тестом (через терминал, для проверки) | На вкладке Actions — красный крестик |

Ещё две проверки:
- команда `/agents` должна показать агентов **reviewer** и **implementer**;
- основная модель — Opus: один раз введите `/model opus` (если агент увидит другую модель, он сам об этом скажет).

После проверки удалите тестовые файлы. Команда `/hooks` в Claude Code показывает, какие замки подключены.

**Если замок не срабатывает:**
- В командах хуков замените `python` на полный путь, например `C:/Users/ИМЯ/anaconda3/python.exe`.
- Проверьте путь к `guard.py` в `settings.json`.
- Перезапустите Claude Code.
