# ticket — одна задача от плана до коммита

Режимы: **старт** (по умолчанию; «следующий» — ближайшая задача по порядку и зависимостям), **продолжить**, **пауза**.

Работай самостоятельно. Останавливайся только по стоп-листу. Модели назначай по разделу «Выбор модели» глобальных правил.

## Старт

**Журнал.** По ходу задачи после каждого шага дописывай в раздел «Где остановились» файла задачи одну строку: шаг · что решил и почему · что дальше. После сжатия контекста верь этому разделу и `git log`, а не памяти. Замок `session_context` сам подгружает этот раздел в новую сессию.

1. **Готовность.** Прочитай файл задачи. Сценарии не утверждены → стоп (стоп-лист): предложи утвердить пакетом сценарии ближайших задач. В связанных ТР/ПР остался маркер `[УТОЧНИТЬ: …]` → стоп (стоп-лист, п. 1): задай этот вопрос с рекомендуемым ответом.
2. **План** (ты, Opus). Прочитай только связанные ПР/ТР и нужные файлы кода. Заново оцени и уточни поле «Сложность» — модель выбирается для каждой задачи отдельно (критерии — «Выбор модели» в глобальных правилах). Запиши в файл задачи: шаги, затрагиваемые файлы, **исполнителя кода** и его модель с причиной. Статус → «в работе». Одобрения плана не жди.
3. **Анонс** — по формату из глобальных правил; дождись ответа про проверки. Ответ запиши в журнал, проверки пользователя — в раздел «Мои тесты до сессии».
4. **Падающие тесты** (ты, Opus). Тесты придумываешь и пишешь ты, пользователь их не пишет. Утверждённые сценарии → `tests/acceptance/`. Видимый результат (отчёт, экран, выгрузка) → сквозной тест в `tests/e2e/`. Свои крайние случаи (ноль, пусто, минус, ошибка источника) → `tests/agent/`. В имени — номер правила или задачи (`test_pr07_…`). Есть расчёт — сверка с эталоном. Проверки пользователя из «Мои тесты до сессии» → `tests/acceptance/` как есть; после создания их не меняй. Запусти: тесты должны упасть, и **по правильной причине** (нет нужной функции или результат не тот), а не из-за опечатки или ошибки импорта. Код в `src/` не трогай.
5. **Проверка плана** — только для 💰-задачи и задачи-«скелета»: скилл `review` в режиме «план» (`reviewer` проверяет план и тесты до кода). Критично → поправь план или тесты, затем дальше.
6. **Код** — назначенный исполнитель:
   - `implementer`: передай путь к файлу задачи, список тестов и **явно модель** (`haiku` или `sonnet`). Он работает по плану и возвращает статус и вердикт.
   - ты сам: по плану, по шагу, после шага — связанные тесты.
   - Правила для любого исполнителя: база — через команду «бэкап + миграция»; тесты не подгонять (считаешь утверждённый тест неверным — стоп-лист); тест упал — по правилу «Не знаешь причину падения» глобальных правил.
7. **Проверка** — запусти `python scripts/validate.py` сам, не полагайся на слова исполнителя. Есть снимки экранов в `exports/screens/` — просмотри их.
   - НЕ ПРОШЛО у `implementer` → верни ему вывод проверки. Дальше — повышение модели по таблице «Выбор модели»; отметь в файле задачи почему. Тот же исполнитель без новых сведений повторно не запускается.
8. **Ревью субагентом — обязательно после каждой задачи, без исключений.** Скилл `review` запускает `reviewer` (Opus, только чтение). Без ревью задача не может быть 🟢.
9. **Исправление замечаний** — тем же исполнителем, что писал код; затем снова шаг 7.
10. **Документы.** Обнови затронутые. Заполни «Итог сессии» по формату из шаблона задачи, статус «готово». Пересобери дорожную карту: `python scripts/roadmap.py`.
    - **Урок задачи** — одна строка в «Итоге сессии»: что пошло не так и как избежать, или «уроков нет». Тот же урок уже был в прошлой задаче → предложи пользователю тест или замок, а не абзац текста.
11. **Отметка ревью** — по скиллу `review`, п. 2, только когда критичных замечаний не осталось.
12. **Коммит и отправка** — по правилу автокоммита глобальных правил. **Одна задача — один коммит**, номер задачи в сообщении (`feat: … (Т-012)`).
13. **Отчёт** — по формату из глобальных правил, без кода. Последней строкой: «Дальше: `/clear`, затем `/ticket следующий`».

## Выборочная проверка (каждая 5-я готовая задача)

Если после этой задачи число задач со статусом «готово» делится на 5 — добавь к отчёту блок «Выборочная проверка»: случайно выбери одну ранее закрытую 🟢-задачу и дай по ней полный отчёт (как 🟡). Выбор — действительно случайный, не самый удачный.

## Пауза (только по прямой команде пользователя или при заканчивающемся контексте — с сообщением ему)

- В файле задачи — «Где остановились»: что сделано, следующий шаг, кто исполнитель, открытые вопросы, какие тесты красные.
- Создай `.claude/PAUSE`, статус «пауза». Без коммита, если проверка красная. Пересобери дорожную карту.
- Создавать `.claude/PAUSE`, чтобы обойти проверку, запрещено.

## Продолжить

- Удали `.claude/PAUSE`, статус → «в работе». Прочитай «Где остановились» и `git status`. Продолжи с указанного шага; анонс повторно не нужен, если ответ на него уже есть в журнале.

## Выгрузка кода — только по просьбе пользователя

`python scripts/export_ticket.py Т-012` (без номера — незакоммиченные изменения) → путь к файлу пользователю.
